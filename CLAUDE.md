# Fresh Calendars

Two sites served from https://freshcalendars.com:

- **Calendar site** (printable calendars, `/when-is/`, holiday pages): generated by `packages/generator` (`pnpm fc <cmd>`), output in `dist/site`.
- **/news/**: Astro 5 static site in `apps/news`, output in `dist/news`. Articles are Markdown files; one file = one URL.

Shared header, footer and site CSS live in `packages/site-chrome/src/index.ts`. Date logic lives in `packages/engine`.

## Team workflow (read this first)

Writers (editors) produce /news/ stories from their own Claude sessions and have full write access to this repository. Publishing is separate: only the site owner deploys.

1. Start from an up-to-date `main` (`git pull origin main`).
2. Write the story with the `news-article` skill (`.claude/skills/news-article/SKILL.md`), in a fresh session per story. It has the full checklist, including the source and PDF rules, and hands research to the `news-researcher` agent (Haiku) and writing to the `news-writer` agent (Sonnet) to keep token use low; `docs/NEWS-COST-GUIDE.md` has the low-cost workflow (batching, briefs, what to avoid). Two companion skills decide what makes the story win: `news-seo` (the query, the angle, the page structure; the playbook `SEO-HARITASI-TAM.md` turned into decisions) and `news-visuals` (a hero no other story has, and the printable).
3. Run the checks below locally. All must pass, with no warnings left unexplained.
4. Commit only the files of your story (and any shared file you deliberately changed) with a clear message, then push straight to `main`. CI repeats the checks on every push; if it fails, fix it with a new commit right away.
5. **Publishing is automatic.** freshcalendars.com runs on Cloudflare (a Worker for pages, R2 for images and printables on `cdn.freshcalendars.com`). When CI passes on a push to `main`, the same workflow uploads the new images and publishes the site (`.github/workflows/ci.yml` → `deploy.yml`, one deploy at a time); a story is live about 6-10 minutes after the push. A story with a future `publishedAt` goes live 10-20 minutes after that time (`scheduled.yml`). The calendar pages are rebuilt daily at 05:25 UTC and monthly (`calendar.yml`). A red CI run is never published: a failing push stays off the site until a new commit fixes it, and it does not hold back green commits pushed before it. **Never run `wrangler deploy` or upload to R2 yourself, never force-push or rewrite `main`'s history, and never ask for `.env` or Cloudflare keys.** The deploy token lives in GitHub Actions only (`docs/DEPLOY.md`).

A branch and pull request are still welcome for large or risky changes (shared components, scripts, `site-chrome`); stories can go straight to `main`.

## Commands

```bash
pnpm install                 # once per clone
pnpm test                    # unit tests
pnpm news:build              # builds dist/news; schema errors in frontmatter fail here
pnpm news:verify             # links, H1, orphans, build leftovers
pnpm news:seo-audit          # SEO and writing rules (all checks must PASS)
pnpm news:abbrev             # 1-second abbreviation check on changed stories, no build (also runs as the pre-push hook)
pnpm news:puzzle-check       # daily puzzle pages vs the saved official NYT data (CI runs it)
pnpm news:puzzle-data <date> # save official puzzle data before writing a puzzle page
pnpm news:serve              # preview on http://localhost:4324/news/ (pass a port to change it)
pnpm smoke:contrast          # WCAG AA text contrast on every built page (after fc gen-meta + news:build); run it by hand when the theme or colors change, CI does not
pnpm news:dashboard          # local read-only editorial report in dist/editorial/ (freshness, duplicates, sources, SEO, CI); never publish it
pnpm news:verify-live [slug] # after auto-publish: the story is live with the right canonical, H1, dates and sitemap row (--wait 600 polls)
```

Do not run Lighthouse (`news:lighthouse`, `smoke:lighthouse`). The goal is fast, correct publishing.

## Non-negotiable content rules

- **Facts only from official or authoritative sources** (government agencies, the company's own site or press release, the publisher of the puzzle, NASA, USNO). Never guess a date, time, price or count. If it is not confirmed, say "not yet announced" and give last year's value labeled as last year.
- If a source blocks automated access (Cloudflare challenge, 403), do not try to get around it. Use another official source; if there is none, a fact goes in only when two or more independent reputable newsrooms agree on it, both listed in `sources:` and named in the text (never Wikipedia or aggregators).
- Election content is nonpartisan: no polls, no predictions, no candidate endorsements.
- **No FAQPage, QAPage or Review schema.** FAQs render as visible `<details>` only (the build handles this).
- Expand every abbreviation on first use, including in `description` (it is the lede): "Eastern Time (ET)". The audit needs the literal `Full Name (ABBR)`.
- Banned words and patterns are listed in `scripts/news-seo-audit.mjs` (BANNED_EN, em dashes, "not X but Y", "in conclusion"). Write plainly, vary sentence length.
- No superlatives you cannot source ("biggest ever"), no invented people or quotes. Byline is the editor responsible for the story's beat, who reviews it before publication: `alex-morgan` (holidays, elections, government deadlines, UK and Canada), `emily-carter` (school calendars, test dates, family planning), `jordan-bennett` (time and clock changes, sky events, calendar guides, retail dates, sports and event schedules). Daily puzzle pages use `news-desk`. Never invent a new person; a new editor needs the publisher's confirmation (`confirmedAt`).
- Every story links at least two calendar pages (`internalLinks`) and up to three related /news/ stories (`related`), and 1-2 existing stories on the same topic link back to it (`13-INBOUND`).
- Updates and error fixes are silent: change the facts and `updatedAt`; no "Last updated" callout and no new `corrections` entry (corrections policy, revised 2026-10-30). Existing correction notes stay.
- No copied patterns in new stories: headlines of 90 characters or fewer, H2s that name the subject instead of another story's heading, no clock-change hook in the description or summary of a story that is not about the time change (`13-*` checks).
- **Every story adds something the top results lack**: a computed table from the official source, a printable built from the story's facts, a fact others missed. A story that only restates one official page is not written (`news-seo`).
- **Every story gets its own hero.** Default: a licensed photo of the real subject with `assets.overlay: true`; otherwise an illustrated scene no story has used (`pnpm fc news-heroes`). `news-assets` refuses a repeated scene or picture and the audit's `12-HERO-UNIQUE` fails the build (`news-visuals`).
- Images are either our own illustrations (`pnpm fc news-assets`: 3D scenes from `packages/generator/render3d/`, flat scenes from `packages/generator/src/art.ts`) or licensed photos fetched with `pnpm fc news-photo` (public domain, CC0, CC BY, CC BY-SA, Pexels License, with credit and license on the page; `assets.overlay: true` adds our text layer and marks the credit "edited"). Never use images from search engines, news sites, stock agencies or social media, and never put our layer on an image we are not licensed to adapt; a credit line is not permission, and taking it down after a complaint does not undo the infringement.
- Printable PDFs are real vector text drawn by our generators (never page images or third-party art), US Letter, with text inside a 0.25 in safe area, only the embedded Sora and Manrope fonts, type of 6 pt or more and contrast of 3:1 or more, and are listed under the story's `downloads:`. The generator checks the layout before printing (`packages/generator/src/printCheck.ts`; `FC_PRINT_DRY=1` checks without writing) and the build stamps their metadata, license, top link and canonical (`apps/news/src/lib/pdf-meta.mjs`); never edit PDFs by hand. Rules: "Printable PDF rules" in the `news-article` skill; the audit's `10-PDF-*` checks must pass.

## Frontmatter limits (enforced by `apps/news/src/content.config.ts`)

| Field | Rule |
|---|---|
| `title` | 20 to 110 characters, equals the H1 |
| `seoTitle` | 20 to 60 characters |
| `description` | 120 to 160 characters |
| `publishedAt` / `updatedAt` | ISO with offset, America/New_York (`2026-10-21T09:30:00-04:00`). The build fails on a future `updatedAt` or correction date; a future `publishedAt` schedules the story, and auto-publish puts it live a few minutes after that time |
| `keywords` | 1 to 5 |
| `summary` | 2 to 4 bullets |
| `type` | `news`, `explainer`, `analysis` or `update` (`news` and `update` need sources) |
| `category` | a file in `apps/news/src/content/categories/` |
| `hero.src` | image at least 1600 px wide (we draw 2400×1350 JPEGs) in `apps/news/src/assets/news/<slug>/` |

| `packages/generator/render3d/`, `src/news3d.ts`, `src/fx.ts` | 3D hero scenes (three.js in headless Chromium, models built from primitives), the two-layer hero renderer, and the finish (bloom, grade, vignette, seeded grain) |

| `.claude/skills/news-seo/`, `news-visuals/` | ranking decisions from the SEO playbook; hero and printable method |
| `.claude/skills/news-puzzles/`, `apps/news/src/content/puzzles/` | daily puzzle pages: method, saved official data, `puzzle-boards.mjs` draws solved boards and tap-to-reveal hints |
| `.claude/agents/news-researcher.md`, `news-writer.md` | Haiku research agent and Sonnet writing agent the skill delegates to |
| `docs/NEWS-ROADMAP.md`, `docs/NEWS-SEO-COMPLIANCE.md` | design of /news/ and the SEO rule map |
| `docs/YAYIN-REHBERI.md`, `docs/DEPLOY.md` | how publishing works (GitHub Actions to Cloudflare; writers only push) |
| `cloudflare/`, `wrangler.jsonc` | the Worker (old-URL 301s, 404s, printables from R2, contact form), the deploy folder builder and the deploy script |
| `SEO-HARITASI-TAM.md` | the SEO playbook the audit cites |
| `scripts/news-*.mjs` | build gates and checks |
| `apps/news/src/lib/similarity.ts`, `topics.ts`, `storygraph.ts` | related stories (TF-IDF similarity, near-copy filter) and topic hubs at `/news/topic/<slug>/`; a story joins a hub when its title head names the topic, so put the topic phrase before the colon |
| `apps/news/src/lib/keydates.ts` (`KEY_DATES`) | dated events: the news home "Coming up", each story's "Key dates" box with add-to-calendar, and the hubs' `.ics` files; add a story's dates here (date from the story's source) |

## Code style

Match the surrounding code: TypeScript, two-space indent, short doc comments that explain why. Keep changes scoped to your story; shared components (`apps/news/src/components`, `site-chrome`) change in their own commit, preferably through a branch and pull request.
